# spec — full-review-and-uiux

## 범위

1. 전체 코드 리뷰 → 확인된 결함 수정 → 테스트 (`review-1.md`)
2. UI·UX 개선안 조사 → 값 대비 위험이 좋은 것부터 구현 → 테스트 (`uiux.md`)
3. 2의 변경을 다시 리뷰 → 수정 → 테스트 (`review-2.md`)

## 하지 않는 것

- 새 Tool·큰 기능 추가 (발열 Tool 은 사용자의 별도 요청이었다)
- 확인하지 못한 지적의 수정 — `review-1.md` 에 "보류" 로 남긴다
- 경계값 지어내기, 시스템 색 직접 쓰기 (프로젝트 규칙)

## 완료 조건

- 고친 것마다 확인 방법과 결과가 `review-1.md` / `uiux.md` / `review-2.md` 에 있다
- 빌드 경고 없음, 설치본이 뜨고 API 가 답한다
- 커밋은 하지 않는다 — 사람이 판단한다
