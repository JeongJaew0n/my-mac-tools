# 덮개를 열 때 암호를 묻는다고 해서 잠든 것이 아니다

## 환경

- macOS 26 (Darwin 25.6.0), Apple Silicon (MacBook)
- 외장 디스플레이 연결 상태에서 덮개를 닫는 클램셸 사용

## 증상

덮개 닫기 잠자기를 막아둔 채로 덮개를 닫고, **닫힌 상태에서 외장 모니터를 뽑았다.**
다시 열었더니 암호를 요구했다. 잠자기 차단이 실패한 줄 알았다.

## 원인

화면 잠금은 **디스플레이가 꺼지는 것**을 기준으로 걸린다. 시스템 잠자기와 무관하다.

덮개를 닫으면 내장 화면이 꺼지고, 외장까지 뽑으면 출력 장치가 0개가 된다. 그래서 설정된
지연 뒤 잠금이 걸린다. 볼 수 있는 화면이 하나도 없으니 잠든 것처럼 보일 뿐, 시스템은 계속
돌고 있다.

## 해결

암호 화면이 아니라 이 셋으로 판정한다.

```bash
sysctl -n kern.waketime            # 마지막으로 깨어난 시각. 잤다 깼으면 갱신돼 있어야 한다
pmset -g log | awk '$4=="Sleep"'   # 해당 구간에 Sleep 기록이 있는지
sysadminctl -screenLock status     # 잠금 지연 (예: 60초)
```

실측 (2026-09-14) — 11:34~12:54 덮개를 닫아둔 구간에 **Sleep 기록 0건**, `kern.waketime`
은 09:33:48 그대로였다. 같은 구간 powerd 로그 215줄에 사용자 프로세스 활동이 끊기지 않고
찍혔고, 12:52 에는 `cloudd` 가 `NSURLSessionTask` 를 완료했다. 12:54:30 에 powerd 가
"화면이 켜져 있어 잠자기 방지" assertion 을 **3시간 20분 41초** 만에 놓았다 — 그동안 내내
깨어 있었다는 뜻이다.

## 재발 방지

고칠 대상이 아니다. 자리를 비운 사이 화면이 잠기는 것은 의도된 보안 동작이고, 앱이 전역
잠금 설정을 건드려서는 안 된다. 화면 잠금은 `loginwindow` 가 화면을 덮는 것일 뿐
프로세스를 멈추지 않는다.

> **화면에 그리는 일은 예외일 수 있다.** 디스플레이가 0개면 렌더링 대상이 없다. 화면
> 캡처·좌표 기반 자동화가 이 조건에서 어떻게 되는지는 확인하지 않았다. 페이지를 직접
> 조작하는 브라우저 자동화는 [`chrome-keeps-running-with-lid-closed.md`](chrome-keeps-running-with-lid-closed.md)
> 에서 문제없음이 확인됐다.
