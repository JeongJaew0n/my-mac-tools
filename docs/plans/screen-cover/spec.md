# spec — screen-cover

## 목표
모든 디스플레이를 지정한 사진 한 장으로 덮는다. 덮여 있는 동안에도 시스템은 잠들지 않고
작업은 그대로 돈다. 버튼을 누르면 해제된다.

## 이것은 잠금 기능이 **아니다**

**잠깐 자리를 비울 때 모니터 앞에 틀어두는 가림막이다.** 이 문장은 README 에도 그대로
싣는다. 오해하면 위험하기 때문이다.

- 인증이 없다. 누구나 버튼을 눌러 해제할 수 있다.
- `Cmd-Q`, 강제 종료(`Cmd-Opt-Esc`), SSH, 사용자 전환으로 뚫린다.
- 앱이 죽으면 커버도 같이 사라진다.

**자리를 비우는 동안의 보안이 목적이라면 macOS 화면 잠금을 쓴다.** 이 기능은 그 대체재가
아니다.

## 확정된 결정

| 결정 축 | 확정 내용 | 근거 |
|---|---|---|
| 덮는 범위 | `NSScreen.screens` 마다 창 하나 | 실측한 이 맥은 디스플레이 3대이고 해상도·배율이 제각각이다 (`1920x1080 @1x`, `1512x982 @2x`, `1920x1080 @1x`). 한 장을 늘려 붙이는 방식으로는 안 된다 |
| 창 레벨 | `CGShieldingWindowLevel()` | 실측값 `2147483628`. `screenSaver`(1000)·`mainMenu`(24) 위라 메뉴 막대와 Dock 을 덮는다 |
| 해제 수단 | ① 항상 보이는 해제 버튼 ② `Enter` 2번 ③ `Esc` 2번 — **셋 다** | 어느 화면 앞에 있든, 마우스를 잡았든 키보드를 잡았든 막히지 않게 한다 |
| 인증 | **넣지 않는다** | 잠금 용도가 아니다. 계정 암호를 앱이 직접 묻는 패턴도 피한다 (피싱과 구조가 같다) |
| 디스플레이 슬립 | 커버 동안 **차단한다** | 막지 않으면 결국 검은 화면이 되고, 그 60초 뒤 진짜 화면 잠금이 걸려 사진을 틀어두는 의미가 사라진다 |
| 슬립 차단 수단 | `IOPMAssertionCreateWithName` (인프로세스) | 아래 참조 |
| 이미지 채우기 | 꽉 채우기(기본) / 맞추기 — 사용자 선택 | 화면 비율이 제각각이라 한쪽만으로는 부족하다 |
| 모니터 착탈 | `NSApplication.didChangeScreenParametersNotification` 구독 | 덮개 기능 테스트에서 실제로 물렸던 시나리오다. 커버 중 모니터를 뽑거나 꽂으면 창을 더하고 뺀다 |
| UI 위치 | 세 번째 탭 | 기존 탭 구조를 그대로 따른다 |

### 슬립 차단에 `caffeinate` 도 `disablesleep` 도 쓰지 않는 이유

`IOPMAssertionCreateWithName(kIOPMAssertionTypePreventUserIdleDisplaySleep, ...)` 를
직접 잡는다. 실측으로 확인했다.

```
IOPMAssertionCreateWithName -> 성공
pmset -g assertions:
  pid 9092(pm): PreventUserIdleDisplaySleep named: "MyMacTools screen cover"
IOPMAssertionRelease -> 성공
프로세스 종료 후 잔존: 0건
```

- **sudo 가 필요 없다.** 덮개 기능과 달리 sudoers 규칙을 깔지 않아도 된다.
- **프로세스가 죽으면 커널이 자동으로 회수한다.** 정리 코드가 돌지 못해도 고아 상태가
  남지 않는다. `pmset -a disablesleep` 이 전역·영구라서 겪은 문제가 여기엔 없다.
- 서브프로세스(`caffeinate`)를 띄우지 않으므로 수명 관리 대상이 하나 줄어든다.
- assertion 에 이름을 붙여두면 `pmset -g assertions` 로 누가 잡고 있는지 바로 보인다.

## 해제 수단 상세

셋 중 무엇이든 하나면 즉시 해제된다.

| 수단 | 동작 | 주의 |
|---|---|---|
| 해제 버튼 | 클릭 즉시 | **모든 화면에** 띄운다. 어느 화면 앞에 앉아 있을지 모른다 |
| `Enter` 2번 | 정해진 간격 안에 두 번 | 간격 상한이 필요하다. 없으면 몇 시간 전에 한 번 눌린 것이 살아 있다 |
| `Esc` 2번 | 정해진 간격 안에 두 번 | `Enter` 와 같은 판정을 쓴다. 키마다 따로 센다 |

키 입력을 받으려면 커버 창이 key 가 돼야 한다. borderless 창은 기본적으로 key 가 될 수
없으므로 `canBecomeKey` 를 열어준다.

## 안전장치

**커버는 앱 프로세스 안에서만 존재한다.** 별도 프로세스로 띄우지 않는다. 앱이 죽으면 커버와
슬립 차단이 동시에 사라지는 것이 마지막 탈출구다.

이미지를 못 읽으면 커버를 띄우지 않는다. 사진 없이 단색으로 덮어버리면 사용자는 무슨 일이
일어났는지 알 수 없다.

## 미확인

- **`Cmd-Tab` 전환기와 강제 종료 창이 shield 레벨 위로 올라오는지.** 실제로 전체 화면을
  덮어봐야 알 수 있어 검토 단계에서는 확인하지 못했다. 구현 중 확인한다. 위로 올라오더라도
  이 기능은 잠금이 아니므로 결함은 아니다.
- 커버 중 다른 앱이 알림 배너를 띄우면 shield 위에 보이는지.
