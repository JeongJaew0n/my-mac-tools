# 남에게 주면 무엇이 문제인가

이 앱은 **한 사람이 자기 맥에서 쓰려고** 만들었다. 그 전제가 깔린 결정이 여러 군데
있어서, 그대로 남에게 주면 기능마다 다른 방식으로 어긋난다. 무엇이 어긋나는지 기능별로
적는다.

전부 실측으로 확인한 것이다. "고치는 값" 은 대략의 크기이지 일정이 아니다.

## 요약

| 심각도 | 무엇 |
|---|---|
| **막힘** | Gatekeeper 가 실행을 거부한다 · Intel 맥에서 안 돈다 |
| **위험** | 덮개 기능이 앱을 지워도 남는다 · sudoers 규칙이 계정에 남는다 · API 가 무인 제어 통로가 된다 |
| **어긋남** | 여러 사용자가 쓰는 맥에서 덮개 기능이 서로를 덮어쓴다 · 커버 사진 경로가 남의 맥에 없다 |
| **불편** | 업데이트 경로가 없다 · 3개 언어뿐 · 지우는 방법이 문서에 없다 |

## 앱 전체

### Gatekeeper 가 막는다 — **막힘**

```
$ codesign -dvvv /Applications/MyMacTools.app
Identifier=com.jjw.mymactools
Signature=adhoc
TeamIdentifier=not set

$ spctl -a -vvv /Applications/MyMacTools.app
/Applications/MyMacTools.app: rejected
```

ad-hoc 서명이라 **받는 사람의 맥에서 실행이 거부된다.** 우클릭 → 열기나 시스템 설정에서
수동으로 허용해야 하고, macOS 버전이 올라갈수록 그 우회가 번거로워진다.

받는 사람에게 "보안 경고가 떠도 무시하고 여세요" 라고 안내하는 것 자체가 나쁜 습관을
가르치는 일이기도 하다.

고치려면 — Apple Developer 계정(연 99 USD), Developer ID 서명, 공증(notarization).
`scripts/build-app.sh` 의 `codesign --force --sign -` 을 실제 인증서로 바꾸고 `notarytool`
단계를 더한다.

### Intel 맥에서 안 돈다 — **막힘**

```
$ lipo -archs .build/MyMacTools.app/Contents/MacOS/MyMacTools
arm64
```

`swift build -c release` 가 **빌드하는 기계의 아키텍처만** 만든다. Apple Silicon 에서
빌드했으므로 arm64 전용이고, Intel 맥에서는 실행되지 않는다.

고치려면 — `swift build --arch arm64 --arch x86_64` 로 유니버설 빌드. 빌드 스크립트
한 줄 수준이지만 Intel 에서 실제로 도는지는 그 기계가 있어야 확인된다.

### 번들 식별자가 개인 네임스페이스다 — **어긋남**

`com.jjw.mymactools` 다. 가진 도메인을 뒤집은 식별자로 바꾸는 것이 맞는데, 바꾸면 기존
사용자의 `UserDefaults`(선택한 탭·언어·커버 사진·단축키)가 **전부 초기화된다.** 나중에
바꿀수록 비싸다.

### 업데이트 경로가 없다 — **불편**

고쳐도 받는 사람에게 닿을 방법이 없다. 매번 `.app` 을 다시 건네야 한다.
Sparkle 같은 업데이터를 붙이려면 서명·공증이 먼저다.

### 지우는 방법이 문서에 없다 — **불편**

`README.md` 에 설치는 있는데 제거가 없다. 아래 셋이 남는다.

```
/Applications/MyMacTools.app
~/Library/Preferences/com.jjw.mymactools.plist     선택한 탭·언어·커버 사진·단축키
/etc/sudoers.d/mymactools                          설치했다면 (아래 참고)
```

`~/Library/Application Support/MyMacTools/api.sock` 은 앱이 종료될 때 스스로 지운다.

## 덮개 닫아도 작업 진행 (`lid`)

### 앱을 지워도 시스템 설정이 남는다 — **위험**

이 기능은 `sudo pmset -a disablesleep 1` 로 **커널 설정**을 바꾼다. 앱의 상태가 아니다.

- **재부팅해도 남는다**
- **앱을 지워도 남는다**
- 켜둔 채로 앱을 지우면 그 맥은 **영영 잠들지 않는다.** 배터리로 덮개를 닫으면 방전된다

앱은 종료할 때 한 번 묻고, 이 앱이 켠 것이면 조용히 되돌린다(`applicationShouldTerminate`).
그러나 **강제 종료되거나 앱이 삭제되면 그 경로를 타지 않는다.**

받는 사람은 이 되돌리는 명령을 알아야 한다.

```bash
sudo pmset -a disablesleep 0
```

`README.md` 에 경고는 있지만 **"앱을 지우기 전에 반드시 끄라"** 는 문장은 없다.

고치려면 — 최소한 문서에 한 줄. 더 하려면 설치 제거 스크립트.

### sudoers 규칙이 계정에 남는다 — **위험**

`scripts/install-sudoers.sh` 는 그 사용자에게 **암호 없는 `pmset` 실행 권한**을 준다.
지금 이 맥에도 설치돼 있다.

```
$ ls -l /etc/sudoers.d/mymactools
-r--r-----  1 root  wheel  221  9월 13 13:36
```

스크립트 자체는 조심스럽게 짜여 있다 — argv 를 와일드카드 없이 끝까지 고정하고,
`visudo -c` 로 문법을 검사하고, 실패하면 되돌린다. 할 수 있는 일도 "맥을 안 재운다"
하나뿐이라 파일 접근이나 임의 명령 실행으로 이어지지 않는다.

문제는 **수명**이다. 앱을 지워도 규칙은 남고, 그 계정에서 도는 **아무 프로그램이나**
암호 없이 그 명령을 부를 수 있다. 받는 사람이 이 규칙의 존재를 잊으면 아무도 지우지 않는다.

```bash
sudo bash scripts/install-sudoers.sh --uninstall
```

고치려면 — 설치 안내와 같은 자리에 제거 안내를 붙인다. 앱 안에서 규칙의 설치 여부를
보여주고 끌 수 있게 하면 더 낫다.

### 여러 사용자가 쓰는 맥에서 서로를 덮어쓴다 — **어긋남**

`pmset -a` 의 `-a` 는 **모든 전원 상태**이고, 설정 자체가 **기계 전역**이다. 사용자 A 가
켜면 사용자 B 의 세션에서도 맥이 안 잠들고, B 가 끄면 A 의 작업이 깨진다.

앱은 켤 때 "이 앱이 켰는지"(`turnedOnByThisProcess`)를 기억하지만 그것은 **프로세스 단위**다.
다른 계정에서 켠 것은 알 수 없다.

고치려면 — 쉽지 않다. 기계 전역 설정을 사용자별로 나눌 방법이 없다. 최소한 켤 때
"이 맥을 쓰는 다른 사람에게도 적용됩니다" 를 알려야 한다.

## 화면 가리기 (`cover`)

### 커버 사진 경로가 남의 맥에 없다 — **어긋남**

사진을 **경로 문자열 그대로** `UserDefaults` 에 넣는다.

```swift
UserDefaults.standard.set(path, forKey: "coverImagePath")
```

설정을 옮겨가면 `/Users/<나>/…` 경로가 남의 맥에는 없다. 앱은 이 경우 덮지 않고 오류를
보여주므로 **깨지지는 않지만**, 받는 사람은 사진을 다시 골라야 한다.

같은 이유로 **샌드박스를 켜면 이 방식이 통째로 막힌다.** 샌드박스에서는 사용자가 고른
파일에 다시 접근하려면 security-scoped bookmark 가 필요하다. 지금은 샌드박스가 아니라서
돌아간다.

### 잠금이 아니다 — **이미 문서에 있음**

앱 안에도 `cover.notALock` 으로 적혀 있다. 누구나 해제할 수 있는 가림막이다. 받는 사람이
자리 비움 잠금으로 오해하면 위험하므로, 공유할 때 이 문장을 앞에 둬야 한다.

### 전역 단축키가 충돌할 수 있다 — **불편**

Carbon `RegisterEventHotKey` 를 쓴다. `NSEvent` 전역 모니터와 달리 **손쉬운 사용 권한이
필요 없다** — 이건 잘 고른 것이다. 다만 이미 쓰이는 조합을 고르면 등록이 실패한다.

## 잠자기 방지 (`screenOff`)

공유했을 때 문제가 가장 적은 기능이다. `caffeinate` 자식 프로세스라 앱이 죽으면 같이
죽고, 시스템에 남는 것이 없다.

### 남는 것 하나 — **불편**

`sleepWhenDone` 이 켜져 있고 시간이 만료되면 `pmset sleepnow` 로 **맥을 재운다.** 받는
사람이 그 설정을 모르고 켜두면 작업 중에 맥이 잠든다. 화면에 caption 으로 알리고는 있다.

## 카페인 목록 · 로컬호스트 (`localhost`)

### 화면에 개인 정보가 그대로 나온다 — **어긋남**

두 목록 모두 **실행 파일 전체 경로**를 보여준다.

```
/Users/jjw/my/Dev/project-novel-writer/.vscode-test/…
/Users/jjw/Library/Java/JavaVirtualMachines/temurin-21.0.10/…
```

사용자 이름, 프로젝트 이름, 설치한 도구가 다 드러난다. 본인이 자기 맥에서 볼 때는
그게 값어치인데, **화면을 공유하거나 캡처를 올릴 때는 유출**이다.

고치려면 — 경로를 `~` 로 줄여 보여주고 전체는 툴팁으로만. 지금도 이름은 줄여 보여주지만
경로 줄은 그대로 나온다.

### 목록이 전부가 아니다 — **오해의 소지**

`PROC_PIDLISTFDS` 가 다른 사용자의 프로세스를 막아서 **내 계정이 띄운 것만** 보인다
(실측 — 188개 거부). root 데몬이 잡은 포트는 안 나온다.

화면에 한 줄로 알리고는 있지만, 받는 사람이 "포트 목록" 이라는 이름만 보고 `lsof` 와
같다고 기대하면 틀린 결론을 낸다.

### "내가 띄운 것" 을 가려낼 수 없다 — **이미 문서에 있음**

`docs/plans/localhost-list/research.md` 에 근거와 반례가 적혀 있다. 라벨을 근거 있는
것만 다는 이유이기도 하다. 공유할 때도 이 한계를 함께 줘야 한다.

## 에이전트용 API

### 무인 제어 통로가 된다 — **위험**

소켓은 `0600` 이라 **다른 사용자**는 못 붙는다. 그러나 그 사용자로 도는 **아무 프로세스나**
붙을 수 있다.

권한 상승은 아니다 — 그 사용자로 도는 프로세스는 원래도 그 사용자의 프로세스를 죽일 수
있다. 새로 생기는 것은 **편의**다. `ports.stop pid=N` 한 줄이면 되고, 어떤 포트를 무엇이
잡고 있는지도 같은 API 가 알려준다.

앱을 준다는 것은 **받는 사람의 맥에서 도는 모든 것에게 이 통로를 연다**는 뜻이다. 에이전트를
쓰는 사람에게는 그게 목적이지만, 모르고 받는 사람에게는 설명이 필요하다.

막아둔 것은 있다 — 시스템 구성요소 중지(`forbidden`), 덮개 기능(`needsHuman`), 자기 자신
중지(`forbidden`).

고치려면 — 설정에 API 끄는 스위치. 지금은 항상 켜져 있고 끌 방법이 없다.

### 소켓 자리가 샌드박스와 충돌한다 — **앞으로의 문제**

`~/Library/Application Support/MyMacTools/api.sock` 이다. 배포를 위해 샌드박스를 켜면
소켓이 컨테이너 안으로 밀려나고 **컨테이너 밖의 에이전트가 닿지 못한다.**

App Store 배포와 이 API 는 함께 갈 수 없다. 둘 중 하나를 골라야 한다.

## 국제화

`ko` · `en` · `ja` 세 언어다. 그 밖의 언어는 `en` 으로 떨어진다. 문자열이 빠지면 화면에
**키 이름이 그대로** 나오도록 되어 있어서(`L10n.callAsFunction`), 새 언어를 넣을 때 빠진
것을 바로 알 수 있다.

`docs/i18n-design.md` 의 문자열 표는 **초기 설계의 키만** 담고 있다. 이후에 붙은
`cover.*`(16) · `menu.*`(2) · `caffeine.*`(15) · `localhost.*`(24, `tab.localhost` 포함) 는 표에 없다. 번역을
외부에 맡기려면 이 표를 먼저 채워야 한다.

## 검증 범위

```
개발·검증:  macOS 26.3.1 / Apple M3 Pro 한 대
배포 타깃:  macOS 14.0
```

**14.0 부터 26.3.1 사이의 어느 버전에서도 실행해 본 적이 없다.** 자동화된 테스트도 없다 —
`Package.swift` 에 `testTarget` 이 없고 `Tests/` 폴더도 없다(실측). 검증은 전부 손으로 했다. 받는 사람의 맥에서 처음
도는 것이 그 버전의 첫 실행이 된다.

## 주기 전에 최소한 할 것

순서대로 값이 크다.

1. **덮개 기능을 끄고 주기.** 켜진 채로 넘어가면 받는 사람 맥이 안 잠든다
2. **되돌리는 명령을 함께 주기** — `sudo pmset -a disablesleep 0`,
   `sudo bash scripts/install-sudoers.sh --uninstall`
3. **Gatekeeper 경고를 어떻게 넘길지 안내하기.** 안 하면 실행조차 안 된다
4. **API 가 켜져 있다는 사실 알리기.** 그 맥에서 도는 프로그램이 앱을 조종할 수 있다
5. **Intel 맥이면 유니버설 빌드가 필요하다고 알리기**
6. 화면을 공유할 일이 있으면 **경로가 나온다는 것** 알리기
