# spec — caffeinate-list

## 목표

잠자기 방지 Tool 아래에 **시스템에서 돌고 있는 caffeinate 를 전부 보여주는 목록**을 둔다.
각 항목이 어떤 옵션으로 떠 있는지 읽고, 옵션마다 무슨 뜻인지 알려주고, 우클릭으로 중지한다.

목적은 "내가 켠 것을 확인"이 아니라 **모르게 돌고 있는 것을 드러내는 것**이다. 내가 켠 것은
이미 상태행(`isRunning`)이 보여준다.

## 확정된 결정

| 결정 축 | 확정 내용 | 근거 |
|---|---|---|
| 목록 범위 | **시스템 전역 모든 caffeinate.** 다른 앱·터미널이 띄운 것 포함 | 이 기능을 설계하는 중에 실제로 Claude Code 가 띄운 `caffeinate -i -t 300` 을 발견했다. 앱이 흘린 것으로 오해하고 있었다 |
| 접힌 상태 배지 | **개수를 표시한다.** 창이 열려 있는 동안 폴링 — 접힘 5초, 펼침 2초 | 접혀 있어도 "돌고 있다"를 알 수 있어야 목적을 달성한다. 펼쳐야만 보이면 여는 사람만 안다 |
| 조회 방식 | **`sysctl` 직접.** `KERN_PROC_ALL` 로 열거, `KERN_PROCARGS2` 로 인자 | 프로세스를 띄우지 않는다. `ioreg` 대신 IOKit, `pmset` 대신 `CGDisplayIsAsleep` 을 쓴 기존 판단과 같은 방향이다 |
| 중지 수단 | `SIGTERM`. **단 이 앱이 띄운 것은 `BlackWorkManager.stop()` 으로 보낸다** | 아래 *함정* 참고. `kill` 로 직접 죽이면 맥이 잠들 수 있다 |
| 남의 프로세스 중지 | **허용한다.** 사용자가 직접 지목한 경우만 | 앱 철학은 "남의 상태를 **조용히** 망가뜨리지 않는다"(`MyMacToolsApp.swift`)다. 명시적 우클릭은 조용함이 아니다 |
| root 소유 항목 | 목록에는 보이되 옵션은 "읽을 수 없음", 중지는 비활성 | 실측: `KERN_PROCARGS2` 가 권한으로 실패한다 |
| 배치 | **기존 `screenOff` Tool 안.** 새 Tool 이 아니다 | 사용자가 "'잠자기 방지'의 아래쪽" 으로 위치를 지정했다. glossary 변경 없음 |
| 옵션 설명 | 호버 툴팁(`.help()`). 알려진 7개 플래그만 설명, 모르는 것은 원문 그대로 | 지어낸 설명이 빈 칸보다 나쁘다 |

## 화면 모양

접힌 상태 — 기존 잠자기 방지 화면 맨 아래에 한 줄이 붙는다.

```
 ● 대기 중
 유지 시간      [0] 시  [00] 분
 화면           [맥북 기본설정대로]
 화면 끄기까지  [3] 초
 □ 끝나면 Mac잠자기 모드
 [        시작        ]
 ────────────────────────────
 ▸ 현재 실행중인 카페인   (2)
```

펼친 상태.

```
 ▾ 현재 실행중인 카페인   (2)
   ┌──────────────────────────────────────┐
   │ pid 63888                    2분 25초 │
   │ [-i] [-t 300]                         │ ← 칩. 호버하면 설명
   │ Claude Code                           │ ← 부모 프로세스
   ├──────────────────────────────────────┤
   │ pid 64711                       방금  │
   │ [-d] [-i] [-m] [-s] [-u] [-t 90]      │
   │ 이 앱                                 │ ← 이 앱이 띄운 것
   └──────────────────────────────────────┘
```

우클릭하면 `중지하기` 하나가 뜬다. root 소유면 비활성이고, 왜 안 되는지 툴팁으로 알린다.

목록이 비면 "돌고 있는 것이 없습니다" 한 줄만 둔다. 빈 상자를 그리지 않는다.

## 옵션 설명 문구

`caffeinate` 의 플래그는 7개다 (`man caffeinate` 실측).

| 플래그 | 호버 설명 |
|---|---|
| `-d` | 디스플레이가 잠들지 않게 막는다 |
| `-i` | 시스템이 유휴 잠자기에 들지 않게 막는다 |
| `-m` | 디스크가 유휴 잠자기에 들지 않게 막는다 |
| `-s` | 시스템이 잠들지 않게 막는다. AC 전원에서만 유효하다 |
| `-u` | 사용자가 활동 중이라고 선언한다. 화면이 꺼져 있으면 켠다 |
| `-t N` | N초 뒤에 해제된다 |
| `-w PID` | 그 프로세스가 끝나면 해제된다 |

세 언어 모두 채운다. 모르는 플래그는 칩으로 그리되 툴팁을 달지 않는다.

## 함정 — 이 앱 소유 프로세스를 `kill` 하면 맥이 잠든다

`BlackWorkManager.handleTermination` 은 이렇게 생겼다.

```swift
guard process === finished else { return }   // stop() 이 이미 정리한 종료
let expired = endDate.map { $0.timeIntervalSinceNow <= 1 } ?? false
let shouldSleep = sleepWhenDone && expired
reset()
if shouldSleep { sleepSystem() }             // pmset sleepnow
```

목록에서 이 앱이 띄운 caffeinate 를 `kill(pid, SIGTERM)` 으로 죽이면 `stop()` 을 거치지 않으므로
`process === finished` 가 참이 되어 **만료 경로로 들어간다.** 만료 1초 전 구간에서 죽이면
`sleepWhenDone` 이 켜져 있을 때 맥이 그냥 잠든다.

그래서 목록의 중지는 대상이 이 앱 소유인지 먼저 보고 갈라야 한다.

- `ppid == getpid()` → `manager.stop()` 을 부른다
- 그 외 → `kill(pid, SIGTERM)`

## 폴링을 언제 멈추나

창이 닫히면 멈춘다. 앱이 살아 있는 동안이 아니다.

메뉴바 작업에서 **창을 닫아도 세션이 끊기지 않게** 바뀌었다(`docs/plans/menu-bar-item/spec.md`).
그래서 "앱이 살아 있으면 폴링" 으로 두면 창을 닫고 며칠 띄워둔 동안 계속 돌게 된다.
보이지 않는 것을 위해 폴링하지 않는다.
