# 메뉴바(상태바) 아이콘 가장자리가 계단처럼 깨져 보인다

## 환경

- macOS 26 (Darwin 25.6.0), Apple Silicon
- **레티나가 아닌 외장 모니터** (1920×1080, 배율 1x)
- `NSStatusItem` + template `NSImage` (PNG 20×20 / `@2x` 40×40, 알파만 쓰는 흑백 그림)
- 원본 그림: AI 생성 이미지(래스터)에서 잘라낸 별·궤도 모양 로고

## 증상

메뉴바 아이콘을 새 로고로 바꿨더니 **곡선 가장자리에 픽셀이 튀어나와** 깨져 보였다.
옆에 있는 시스템 아이콘들은 매끈하다. 오류는 없다.

## 원인

아이콘을 만들 때 픽셀마다 "칠함 / 안 칠함"만 고르게 했다(**이진화**, 알파 0 아니면 255).

- 1x 화면에서는 20px 그림이 **늘어나거나 줄지 않고 그대로** 찍힌다. 곡선을 0/255
  두 값으로만 그리면 계단이 그대로 보인다.
- 레티나(2x)에서는 40px 그림이 쓰여 계단이 덜 보인다. 그래서 레티나 화면만 보고
  만들면 이 문제를 놓친다.

이진화를 했던 이유는 예전 로고 때문이었다. 선이 가늘고 틈이 좁은 그림은 가장자리를
반투명으로 두면 메뉴바의 반투명 틴트와 곱해져 **전체가 흐릿하게** 떴다. 그 판단을
곡선 위주의 새 로고에 그대로 적용한 것이 문제였다.

## 해결

**가장자리를 덮인 비율만큼 반투명으로 남긴다(안티앨리어싱).** SF Symbols 를 비롯한
시스템 아이콘이 다 이렇게 그려진다.

1. 원본 마스크를 최종 크기의 8배로 그린다(슈퍼샘플).
2. 거기서 그림/바탕을 임계값으로 가른다.
3. 최종 픽셀 하나에 들어가는 8×8 칸 중 **그림인 칸의 비율을 알파로** 쓴다.

```swift
// 이진화 (계단이 진다)
outData[i + 3] = Double(hits) / Double(cell) >= 0.5 ? 255 : 0
// 안티앨리어싱 (매끈하다)
outData[i + 3] = UInt8((Double(hits) / Double(cell) * 255).rounded())
```

원본이 **AI 생성 래스터**면 그 자체에 가장자리 잡티가 있다. 그대로 줄이면 잡티도 함께
남으므로, 마스크를 먼저 깨끗하게 만든다.

1. 밝기로 그림 영역만 마스크로 딴다.
2. 마스크를 4배로 키우고 가우시안 블러(반경 10px 안팎)를 준다.
3. 128 에서 다시 이진화한 뒤 원래 크기로 줄인다 → 잡티가 사라지고 곡선이 매끈해진다.

이 깨끗한 마스크를 위 안티앨리어싱 단계의 원본으로 쓴다.

**확인 방법:** 메뉴바 회색 바탕에 흰 그림으로 합성해 **실제 픽셀 크기 그대로** 10배
최근접(nearest) 확대로 나란히 비교했다. 사용자도 실제 메뉴바에서 확인했다
("좋은데").

### 확인하다 헷갈린 것 — 캡처가 통째로 어둡게 찍힘

설치 직후 `screencapture` 로 메뉴바를 찍었더니 아이콘이 흐릿하게 나와 반투명 가장자리
탓인 줄 알았다. 실제로는 **그 순간 메뉴바 전체가 어두웠다** — 옆 시스템 아이콘의 최대
밝기도 똑같이 175 였다(정상일 때는 243). 아이콘만 보고 판단하지 말고 **옆 아이콘과 픽셀
값을 비교**한다. [미정] 메뉴바가 왜 어둡게 찍혔는지(비활성 상태, 다른 Space 등)는 확인하지
않았다.

### 통하지 않은 시도 (예전 로고에서)

| 시도 | 결과 |
|---|---|
| 큰 마스크를 그냥 줄이기 | 원본 잡티와 가는 틈이 반투명 회색으로 번져 흐려진다 |
| 최종 크기에서 이진화 | 가는 틈은 살지만 **곡선이 계단**이 된다 (이 글의 증상) |
| 침식으로 틈 벌리기 | 가는 선이 먼저 사라진다 |

결론: 반투명 가장자리가 흐려 보이는 건 **그림이 메뉴바 크기에 비해 너무 가는 탓**이지
안티앨리어싱 탓이 아니다. 그때는 그림을 굵게 고친다.

## 재발 방지

- 메뉴바 아이콘을 바꾸면 **1x 와 2x 둘 다** 실제 크기로 확인한다. 레티나 화면만 보면
  1x 계단을 놓친다.
- 기본은 안티앨리어싱으로 굽는다. 이진화는 쓰지 않는다.
