## 9. 범주 필터 · 포트 검색 (2026-09-21 추가)
- [x] `PortCategory` — 전체 · 시스템 · well-known · 내 터미널 · 기타.
      라벨과 같은 축을 쓴다. 화면 라벨과 고를 수 있는 범주가 어긋나면 무엇으로 걸러진
      것인지 알 수 없다. `기타` = 라벨이 하나도 없는 것
- [x] `visiblePorts` — 범주 + 검색어 적용. 화면은 이것만 그린다
- [x] 검색은 **숫자만** 쓴다. 글자는 버린다 (실측 — `"abc"` → 필터 없음, `"12x3"` → `123`)
- [x] 부분 일치(`contains`). `"87"` 이 `9876` 도 잡는다 — 찾는 포트를 숨기지 않는 쪽을 택했다
- [x] `isRunning` 은 **전체**를 본다. 필터에 걸러진 것과 듣는 것이 없는 것은 다른 상태다
- [x] 결과가 비었을 때 문구를 가른다 — `localhost.empty`(없음) vs `localhost.noMatch`(안 맞음)
- [x] 필터가 걸려 있으면 `N / M개 보임` 을 보여준다. 필터를 잊고 "포트가 사라졌다" 고
      오해하지 않게
- [x] 문구 5개 × 3언어
- [x] 범주별 결과 (실측 — 전체 22 / 시스템 3 / well-known 0 / 내 터미널 1 / 기타 18)
- [x] 검색 (실측 — `"8765"` → 1개, `"87"` → 8765·9876, `"000"` → 5000·7000)
- [x] 범주+검색 조합 (실측 — 내 터미널 + `"8"` → 8501, 시스템 + `"8"` → 0개)
- [x] `isWellKnown` 경계 (실측 — 1023 true / 1024 false. 합성 값으로 확인했다.
      1024 미만을 듣는 프로세스는 root 가 필요해 실물로 만들지 못했다)
- [x] 실행 검증 — 20초 생존, CPU 0.0%, 크래시 리포트 없음, 로그에 오류 없음
