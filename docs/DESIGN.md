# 디자인 시스템

MyMacTools UI 에서 **실제로 쓰이고 있는 규칙을 뽑아낸 문서**다. 이상적인 안이 아니라
현재 코드의 사실이며, 수치는 `Sources/MyMacTools/Design.swift` 에 토큰으로 들어 있다.
토큰을 도입하면서 값은 하나도 바꾸지 않았다 — 정리되지 않은 부분도 그대로 옮겼고,
무엇을 손볼지는 맨 아래 "정규화 제안" 에서 정한다.

---

## 1. 이 UI 가 지키는 원칙

### 보이는 값은 전부 실제 상태에서 파생된다

앱이 따로 기억하는 값으로 화면을 그리지 않는다. 두 기능 모두 **시스템 상태**를 바꾸고
그 값은 앱 밖에서도 바뀔 수 있기 때문이다.

- 상태 점은 매니저의 `isRunning` 을 그대로 따른다.
- `isRunning` 은 커널의 `SleepDisabled`(덮어도 작업), 자식 프로세스 생존(잠자기 방지)에서 온다.
- 어긋날 수 있는 최대 시간은 1초다. 티커가 매 초 실제 값을 다시 읽는다.

이 원칙을 어겨서 실제로 버그가 났다 — 상태는 "꺼짐" 인데 카운트다운만 계속 돌았다.
경위는 [`troubleshootings/project-specific/status-off-but-countdown-keeps-running.md`](troubleshootings/project-specific/status-off-but-countdown-keeps-running.md) 에 있다.

### 돌고 있는 것은 어느 화면에서도 보인다

탭으로 기능을 나눴어도 **동작 여부만은 탭 라벨에 남긴다.** 덮어도 작업은 앱을 꺼도
설정이 남으므로, 탭 뒤에 숨기면 "이 맥은 잠들지 않는다" 는 사실이 화면 어디에도 없게 된다.

### 프로그램이 판단하지 않는 것은 글로 알린다

전원 상태를 감시하거나 막지 않는다. 대신 주의사항을 버튼 위에 **항상** 띄운다.
판단은 사용자 몫이라는 것이 제품 결정이다.

### 할 수 없는 조작은 잠그고, 이유를 옆에 쓴다

`.disabled()` 로 막되 그 이유를 caption 으로 함께 보여준다. 눌러도 아무 일이 없는
컨트롤을 남기지 않는다.

## 2. 창

| 항목 | 값 | 근거 |
|---|---|---|
| 폭 | 기본 `380` / 최소 `320` | 380 은 탭 라벨 넷이 한 줄에 들어가는 폭 |
| 내용 높이 | 기본 `336` / 최소 `240` | 가장 긴 탭의 내용 높이를 기본값으로 |
| 정렬 | `.top` | 내용이 짧은 탭은 아래가 남는다 |
| 크기 조절 | `.windowResizability(.contentMinSize)` | 사용자가 늘리고 줄일 수 있다 |
| 처음 크기 | `.defaultSize(380, 336 + 32)` | 아래 함정 4 참고 |
| 제목 | 없음 (창 타이틀바가 `CFBundleName` 을 씀) | 본문에 제목을 또 두면 상단이 3단이 된다 |

**기본 높이를 가장 긴 탭에 맞추는 이유**: 탭마다 내용 높이가 달라 그대로 두면 탭을 바꿀
때마다 창이 튄다. `ideal` 로 주면 처음 열릴 때만 정해지고 그 뒤로는 사용자가 정한 크기를
따르므로, 튀지 않는 성질은 유지되면서 크기 조절이 열린다. 짧은 탭의 아래 여백이 그 대가다.

**크기를 고정하지 않는 이유** (2026-09-22): 카페인·포트 목록이 들어오면서 내용이 길어졌다.

**크기는 macOS 가 알아서 기억한다.** `WindowGroup` 에 id 를 준 순간 프레임 자동저장이
붙어 `UserDefaults` 의 `NSWindow Frame main-AppWindow-1` 에 쌓인다. 앱이 저장하는 것이
아니므로 코드에는 흔적이 없다. 기본 크기로 되돌리려면 그 키를 지운다.

```bash
defaults delete com.jjw.mymactools "NSWindow Frame main-AppWindow-1"
```

**넘칠 때**: 내용을 `ScrollView` 로 감싸고 `.scrollBounceBehavior(.basedOnSize)` 를 준다.
들어가면 스크롤바도 바운스도 없고, 오류 문구가 늘어날 때만 스크롤된다.

### 높이를 다룰 때의 함정 세 가지

실제로 셋 다 밟았다.

1. **`.contentSize` 에서는 `minHeight` 로 창이 커지지 않는다.** 내용의 *ideal* 크기를
   쓰므로 최소치를 줘도 무시된다. 크기 조절을 열려면 `.contentMinSize` 로 바꿔야 한다 —
   `.contentSize` 는 ideal 로 창을 못 박아 사용자가 끌어도 움직이지 않는다.
2. **창 높이 ≠ 내용 높이.** 창 프레임에는 타이틀바 32pt 가 들어 있다. 창 높이를 그대로
   내용 높이에 넣으면 그만큼이 통째로 빈다.
3. **`Spacer(minLength: 0)` 를 상단 정렬용으로 쓰지 않는다.** 창이 632 까지 부풀었다.
   `.frame(alignment: .top)` 이면 충분하다.
4. **`.contentMinSize` 로 바꾸면 뷰의 `idealWidth/Height` 가 무시된다.** SwiftUI 기본값인
   900x450 으로 열린다. 처음 크기는 `.defaultSize` 로 줘야 한다. 그리고 `.defaultSize` 는
   **창 전체** 크기라 내용 높이에 타이틀바 32pt 를 더해야 한다 — 함정 2 와 같은 실수다.

> 측정할 때: 내용의 자연 높이를 재려면 `ScrollView` 와 고정 높이를 **둘 다** 빼야 한다.
> `ScrollView` 는 주어진 높이를 다 먹어서 측정을 무의미하게 만든다.
> 그리고 `CGWindowListCopyWindowInfo` 가 보고하는 bounds 는 디스플레이 구성에 따라
> 달라진다. 값을 비교할 때는 같은 구성에서 재야 한다.

## 3. 간격

토큰은 크기가 아니라 **쓰임**으로 이름 짓는다. `spacing8` 이 아니라 `inRow` 라고 부르면
값을 바꿀 때 어디가 영향받는지 이름만으로 안다.

| 토큰 | 값 | 쓰이는 곳 |
|---|---|---|
| `Spacing.none` | 0 | 탭바와 본문 (사이는 `Divider` 가 가른다) |
| `Spacing.tabItem` | 4 | 탭바 항목 사이 |
| `Spacing.listRow` | 5 | 주의사항 줄 사이, 불릿과 글 사이 |
| `Spacing.dotToLabel` | 6 | 탭 라벨의 점과 글 사이 |
| `Spacing.inRow` | 8 | 한 줄 안에서 라벨과 컨트롤 사이 |
| `Spacing.settingsRow` | 10 | 설정 항목 사이 |
| `Spacing.lidBlock` | 12 | 덮어도 작업 탭의 블록 사이 |
| `Spacing.sleepBlock` | 16 | 잠자기 방지 탭의 블록 사이 |
| `Padding.content` | 20 | 탭 본문 둘레 |
| `Padding.tabBarHorizontal` / `Top` / `Bottom` | 12 / 10 / 8 | 탭바 둘레 |
| `Padding.tabItemVertical` | 6 | 탭 항목 위아래 (눌리는 영역) |

## 4. 색

의미로만 쓴다. 브랜드 색이 없고 전부 시스템 색이라 다크/라이트가 자동으로 맞는다.

| 색 | 뜻 | 쓰이는 곳 |
|---|---|---|
| `.green` | 동작 중 | 상태 점 |
| `.gray` | 꺼짐 | 상태 점 |
| `.orange` | 곧 일어남 · 주의 | 화면 꺼짐 카운트다운, 재차 끄기 유예, 주의사항 아이콘 |
| `.red` | 실패 | 화면 계속 끄기 포기, 자동 해제 실패, 오류 |
| `.secondary` | 보조 설명 | 단위, caption, 주의사항 본문, 남은 시간 |
| `.quaternary` | 선택된 탭 배경 | 탭바 |

**녹색 점은 직접 그린다.** `Circle().fill(...)` 이다. macOS 의 `TabView` `.tabItem` 은
이미지를 template 으로 렌더링해 색이 죽기 때문에, 탭바를 직접 그리는 쪽을 택했다.

## 5. 글자

| 용도 | 스타일 |
|---|---|
| 상태 줄 | `.body` |
| 숫자가 흐르는 표시 (남은 시간, 카운트다운) | `.system(.callout, design: .monospaced)` |
| 보조 설명 · 주의사항 · 오류 | `.caption` |
| 선택된 탭 이름 | `.semibold` (나머지는 `.regular`) |
| 주의사항 제목 | `.medium` |

**등폭은 숫자가 1초마다 바뀌는 곳에만** 쓴다. 비등폭이면 자릿수가 바뀔 때 글자가 흔들린다.

## 6. 반복되는 조각

### 상태 줄
점(`Size.statusDot` = 10) + 글(`.body`). **두 탭 모두 가운데 정렬**이다.
덮어도 작업 탭은 주의사항 때문에 `VStack(alignment: .leading)` 이라,
상태 줄만 `.frame(maxWidth: .infinity)` 로 펴서 가운데에 맞춘다.

### 라벨 + 컨트롤 한 줄
```
Text(라벨)  Spacer(minLength: 4)  Picker().labelsHidden().fixedSize()  Text(단위).secondary
```
`HStack(spacing: Spacing.inRow)`. 라벨은 왼쪽, 컨트롤은 오른쪽으로 몰린다.

### 주의사항 블록
경고 삼각형(`.orange`) + 제목(`.medium`), 그 아래 `•` 불릿 목록.
전체 `.caption` + `.secondary`, `VStack(alignment: .leading, spacing: Spacing.listRow)`.
긴 줄은 `.fixedSize(horizontal: false, vertical: true)` 로 접는다.

### 기본 동작 버튼
탭마다 하나. **글자 폭만큼, 가운데.** 창 폭을 채우지 않는다.

아이콘이 상태 점을 겸한다 — 돌고 있으면 초록, 아니면 `secondary`. 320pt 에 탭 넷이라
점·아이콘·글자를 다 넣을 자리가 없다. 직접 그리는 탭바라 `.tabItem` 과 달리 색이
template 으로 죽지 않는다.
`leading` 정렬 컨테이너 안에서는 양쪽 `Spacer` 로 가운데에 둔다 —
버튼에 `.frame(maxWidth: .infinity)` 를 걸면 버튼 자체가 늘어나 모양이 달라진다.

### 탭 항목
점(`Size.tabDot` = 8, 본문보다 작다) + 이름. 선택되면 `.quaternary` 배경
(`RoundedRectangle(cornerRadius: 6)`)과 `.semibold`.
`.buttonStyle(.plain)` 에 배경을 직접 그린다 — `.accessoryBar` 같은 기성 스타일에
맡기면 렌더링을 보장할 수 없다.

## 7. 글쓰기 규칙

- **화면에 보이는 말로 쓴다.** `시스템 설정대로` 를 `맥북 기본설정대로` 로 바꾼 이유가
  이것이다. 사용자는 `pmset displaysleep` 값을 알지 못한다.
- **거짓이 되는 문구를 두지 않는다.** 상태 줄이 세 갈래인 이유다 —
  "화면 꺼짐" 은 끄는 모드에서만 참이고, 맥북 기본설정대로 두는 모드는 언젠가 꺼지므로
  "계속 켜짐" 이라고도 할 수 없다.
- **잠긴 컨트롤의 이유는 같은 화면에서 읽히게 한다.** 이유가 다른 탭에 있으면,
  문구가 그 기능의 이름을 직접 불러 옮겨가지 않아도 알 수 있게 한다.
- 문자열은 `Resources/{ko,en,ja}.lproj` 셋을 **항상 함께** 고친다. 값이 없으면 키가
  그대로 화면에 나오므로 누락은 눈에 띈다.

## 8. 정규화 제안 (미적용, 검토 대상)

아래는 **아직 코드에 반영하지 않았다.** 지금 값들은 그때그때 정해진 것이라 눈금이 고르지 않다.

### 8.1 간격 눈금이 없다
쓰이는 값: `0, 4, 5, 6, 8, 10, 12, 16, 20`. 5 와 6, 10 과 12 가 섞여 있는데
시각적으로 구분되지 않는다. 4의 배수로 줄이면:

| 지금 | 제안 | 영향 |
|---|---|---|
| 5 | 4 | 주의사항 줄 간격이 1pt 촘촘해짐 |
| 6 | 8 | 탭 점과 글이 2pt 벌어짐 |
| 10 | 8 또는 12 | 설정 항목 간격 |
| 12 / 16 | 하나로 통일 | 두 탭의 블록 간격이 다를 이유가 없다 |

→ 눈금을 `4 / 8 / 12 / 16 / 20` 으로 줄이는 안.

### 8.2 두 탭의 블록 간격이 다르다
잠자기 방지 16, 덮어도 작업 12. 의도한 차이가 아니라 따로 만들다 생긴 차이다.
통일하면 탭을 바꿀 때 리듬이 유지된다. 다만 통일하면 **내용 높이가 바뀌어
고정 높이(336)를 다시 재야 한다.**

### 8.3 `.callout` 이 두 군데서 겉돈다
`progress.noLimit` 과 `status.keepOffFailed` 만 `.callout` 이고, 성격이 비슷한 다른
문구는 `.caption` 이다. 통일 후보.

### 8.4 짧은 탭의 아래 여백 36pt
고정 높이의 대가다. 선택지는 셋.
1. 그대로 둔다 (현재)
2. 고정을 풀어 탭마다 창 크기가 바뀌게 한다 — 전환할 때 36pt 움직인다
3. 잠자기 방지 탭에 내용을 더해 높이를 맞춘다

### 8.5 기본 버튼 단축키가 한쪽에만 있다
잠자기 방지 버튼에는 `.keyboardShortcut(.defaultAction)` 이 있고 덮어도 작업에는 없다.
탭마다 하나씩만 화면에 있으므로 충돌하지 않아 양쪽에 줄 수 있다.
**다만 덮어도 작업은 시스템 설정을 바꾸는 동작이라, Return 으로 쉽게 발동하는 게
바람직한지 판단이 필요하다.** 그래서 임의로 추가하지 않았다.

### 8.6 기능 이름이 두 가지로 불린다
탭 라벨은 `덮어도 작업`, 경고 문구는 `'덮개 닫아도 작업 진행'`.
화면에 없는 이름으로 부르고 있다. 통일 대상은 `caption.sleepBlockedByLid`,
`quit.title`, `quit.body` 3개 × 3개 언어.
