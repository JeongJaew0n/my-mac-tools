# context — settings-window

## 원 요청 (2026-09-26)

> 이제 mac기준 좌상단에서 '설정'같은 거 할수 있잖아? 여기에 설정 만들어줘.
> 설명 화면에서는 어떤 기능이 우리 기본 탭에 표시될건지 선택할 수 있게 해줘. on/off 토글로.

"좌상단" 은 애플 메뉴 옆의 **앱 메뉴**(`MyMacTools`)다. macOS 에서 설정은 거기 `설정…`
으로 들어가고 `⌘,` 가 붙는다.

## 왜 숨긴 것을 저장하나

보이는 것을 저장하는 쪽이 자연스러워 보인다. 그런데 그러면 **나중에 Tool 을 추가했을 때
그 목록에 없으므로 기본으로 숨겨진다.** 새 기능을 만들고도 설정을 열어 켜야 보인다.

숨긴 것만 저장하면 모르는 Tool 은 자동으로 보인다. 이 앱은 Tool 이 계속 늘어왔다
(잠자기 방지 → 덮개 → 화면 가리기 → 로컬호스트). 늘어나는 쪽을 기본값으로 둔다.

## 왜 마지막 하나를 못 끄게 하나

탭이 0개면 창이 빈 화면이 된다. 되돌리는 길이 설정 창뿐인데, 그 창을 여는 법을 모르면
갇힌다. `⌘,` 를 아는 사람에게는 사소하지만 모르는 사람에게는 앱이 고장 난 것과 같다.

토글을 잠그고 왜 잠겼는지 툴팁으로 알린다. 눌리지 않는 이유를 쓰지 않으면 버그로 보인다.

## 왜 메뉴바는 안 건드리나

요청은 "**기본 탭**에 표시될 것" 을 고르는 것이다. 탭에서 치웠다고 그 기능을 쓸 수
없게 만드는 것은 다른 이야기다.

그리고 이 앱은 창을 닫고 메뉴바로 쓰는 흐름이 이미 있다(`docs/power.md` — 창을 닫으면
폴링이 멈춘다). 탭에서 숨긴 Tool 을 메뉴바에서도 지우면 그 흐름이 끊긴다.

## 기각 — 직접 `NSWindow` 를 띄우기

앱 메뉴의 `설정…` 항목과 `⌘,` 를 손으로 만들어야 한다. SwiftUI 의 `Settings` 씬은
둘 다 자동으로 붙여준다. 관례를 따르는 쪽이 코드도 적다.

## 검증에서 막힌 것

탭이 실제로 사라지는 모습을 **접근성 트리로 셀 수 없었다.** 탭바를 SwiftUI 로 직접
그려서(`docs/DESIGN.md` — 기성 스타일을 쓰지 않는 이유) 자식 요소가 AX 에 노출되지
않는다. 화면 캡처는 이 터미널에 화면 기록 권한이 없어 실패한다.

대신 관찰 가능한 것으로 확인했다 — `hiddenTabs` 저장, 마지막 하나의 체크박스 비활성,
그리고 **보던 탭을 숨겼을 때 `selectedTab` 이 옮겨가는 것**. 마지막 것이 본문이 비지
않는다는 가장 좋은 증거다.
