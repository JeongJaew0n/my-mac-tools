# spec — ui-kit 원칙 점검

## 요구사항
세션마스터 전달(사용자 지시, 2026-11-17): ui-kit(`~/my/Dev/ui-kit`, 0.3.1)이 이 앱에 잘 적용됐는지 보고,
색·글자·간격·모서리·움직임 토큰과 원칙(대비 4.5:1, 누르는 영역, 동작 줄이기, 색은 뜻 이름으로)을
SwiftUI 쪽에 맞출 가치가 있는지 판단한다. 가치가 있으면 하고, 없으면 이유를 적는다. 묻지 않고 추천안으로 정한다.

## 전제
ui-kit 은 **웹 키트**(CSS·JS)다. 이 앱은 SwiftUI 네이티브 macOS 앱이고 웹 화면이 없다
(`design/build/tokens.css` 는 토큰 생성물이지 화면이 아니다). 그래서 키트 파일을 들일 곳은 없고,
따질 것은 **원칙**과 **토큰 구조**다.

## 판단
| # | ui-kit | 이 앱의 지금 | 판단 | 이유 |
|---|---|---|---|---|
| 1 | 토큰 값(간격 4·8·12…, 모서리, 글자 15·17, 자체 글꼴) | `design/tokens.json` 자체 눈금, 시스템 글꼴 | **값은 들이지 않는다** | ui-kit 값은 터치·웹 기준이다(주 버튼 48). macOS 앱은 시스템 글꼴과 시스템 컨트롤 크기(HIG)를 따라야 다른 Mac 앱과 같은 손맛이 난다. **구조는 이미 같다** — 원시 눈금·역할 이름·제품 값 세 층, 화면 코드는 역할 이름만 쓴다 |
| 2 | 대비 — 글자 4.5, 모양 3, "생성기와 시험이 지킨다" | 값은 `color-tokens/spec.md` 에 손으로 잰 표뿐, 시험 없음 | **들인다** | 테마나 원시 색을 바꾸면 아무도 모르게 깨질 수 있다. `build-tokens.py --check` 가 대비도 본다 |
| 3 | 누르는 영역 — 어떤 것도 24 아래로 가지 않는다 | 직접 그린 누르는 곳 셋이 글자 높이(약 15~17pt): 카페인 목록 펼침 제목, IntelliJ '색 더 보기', Mac 정보 IP 복사 | **들인다(24 하한만)** | macOS HIG 최소(20pt)에도 못 미친다. 역할 토큰 `size.hitMin` 을 두고 셋에 건다. **시스템 컨트롤(`.small` 버튼·피커)은 손대지 않는다** — macOS 가 그리는 크기이고, 48 같은 터치 치수는 데스크톱 앱에 맞지 않는다 |
| 4 | 동작 줄이기 | 애니메이션을 쓰는 곳이 없다 | 해당 없음 | 지시대로 모션 체계는 따로 만들지 않는다(ui-kit 0.4 대기) |
| 5 | 색은 뜻으로(`accent`·`danger`·`warning`·`success`) | `accent`·`statusError`·`statusWarning`·`statusRunning`·`statusIdle` | **이미 지킨다. 이름은 바꾸지 않는다** | 뜻 이름이라는 원칙은 같다. ui-kit 이름으로 갈면 화면 코드 전부를 바꾸는데 얻는 것이 없다. 대응: danger=`statusError`, warning=`statusWarning`, success=`statusRunning` |
| 6 | 말은 해요체로 | 합니다체("열지 못했습니다") | **들이지 않는다(추천), 사람 확인 필요** | macOS 의 경고창·메뉴 문구가 합니다체다. 앱 문구만 해요체로 바꾸면 한 화면 안에서 말투가 갈린다. 다만 사용자의 다른 앱들과 말투를 맞추고 싶다면 뒤집을 수 있는 결정이라 보고에 남긴다 |
| 7 | 한 화면에 한 가지, 주 버튼 하나 | 탭마다 기본 동작 버튼(`PrimaryButtonStyle`) 하나 | 이미 지킨다 | — |
| 8 | 웹 화면은 키트로 | 웹 화면 없음 | 해당 없음 | — |
