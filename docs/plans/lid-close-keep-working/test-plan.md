# test-plan — lid-close-keep-working

기능 A("화면 끄고 작업", 기존 `BlackWorkManager`)와 기능 B("덮개 닫아도 작업 진행", 신규)를
동시 실행 가능하게 설계했다. 두 기능의 의도가 정면으로 부딪히는 지점이 있으므로,
**앱 코드를 쓰기 전에 시스템 레벨에서 사실을 확정한다.**

## 두 기능이 시스템에 하는 일

| | 기능 A | 기능 B |
|---|---|---|
| 잠자기 차단 | `caffeinate -i` (assertion, 자식 프로세스) | `pmset -a disablesleep 1` (커널 플래그) |
| 화면 | `pmset displaysleepnow` 로 **끈다** | 건드리지 않음 |
| 유지 | `keepScreenOff` 시 깨어나면 다시 끔 (3회 실패하면 `.gaveUp`) | 해당 없음 |
| 종료 시 | `sleepWhenDone` 이면 `pmset sleepnow` 로 **재운다** | 해당 없음 |
| 잔류 | 없음 (앱 죽으면 caffeinate 도 죽음) | **있음** (재부팅해도 유지) |

## 상충 지점 6개

| ID | 상충 | 예상 증상 | 심각도 |
|---|---|---|---|
| **C1** | `disablesleep=1` 에서 `pmset displaysleepnow` 가 막히는가 | A 의 핵심 동작 불능. `keepScreenOff` 켜져 있으면 3회 실패 후 `.gaveUp` 빨간 문구 | **높음** |
| **C2** | `disablesleep=1` 에서 `pmset sleepnow` 가 막히는가 | A 의 "끝나면 잠자기"가 조용히 무시됨 | 높음 |
| **C3** | 화면이 꺼진 상태에서 `disablesleep` 값을 바꾸면 화면이 깨어나는가 | B 를 켜는 순간 A 가 꺼둔 화면이 되살아남 | 중간 |
| **C4** | B 의 인증 다이얼로그를 A 가 꺼버리는가 | 암호 입력 중 화면이 꺼짐. `keepScreenOff` 유예 10초 뒤 재차 블랭크 | **높음** |
| **C5** | A 를 중지해도 B 는 계속 켜져 있음 | 사용자가 "다 껐다"고 오인 | 낮음(표시 문제) |
| **C6** | B 가 켜져 있으면 A 의 `caffeinate -i` 는 무의미 | 중복일 뿐 해롭지 않음 | 없음 |

C1~C3 은 시스템 사실이므로 **Phase 1 에서 앱 없이 확정한다.**
C4~C6 은 앱 동작이므로 Phase 2 로 미룬다.

---

## Phase 1 — 시스템 레벨 (앱 코드 불필요, 지금 실행 가능)

`docs/plans/lid-close-keep-working/probe-conflicts.sh` 를 `sudo` 로 실행한다.
`CGDisplayIsAsleep` 프로브로 판정하므로 기능 A 의 실제 판정 로직과 동일하다.

| 테스트 | 절차 | 통과 기준 |
|---|---|---|
| **T1 대조군** | `disablesleep=0` → `displaysleepnow` | 화면이 꺼진다 (ASLEEP) |
| **T2 (C1)** | `disablesleep=1` → `displaysleepnow` | 화면이 꺼진다. **꺼지지 않으면 동시 실행 설계를 재검토** |
| **T3 (C3)** | 화면을 끈 상태에서 `disablesleep` 0→1 | 화면이 깨어나지 않는다 |
| **T4 (C2)** | `disablesleep=1` → `pmset sleepnow` | **잠들지 않아야 정상**. 잠들면 B 가 무력한 것 |

T4 는 성공 시 맥이 실제로 잠들어 스크립트가 중단되므로 `--sleepnow` 인자로 명시적 옵트인.
결과는 각 테스트 직후 파일에 기록되므로 중단돼도 앞 결과는 남는다.

소요: 약 40초. 화면이 3~4회 껐다 켜진다.

## Phase 2 — 앱 레벨 (구현 후)

### 2-1. 상태 조합 매트릭스
| A | B | 확인 사항 |
|---|---|---|
| OFF | OFF | 기본 상태. 두 버튼 모두 "시작" |
| ON | OFF | 기존 기능 회귀 없음 |
| OFF | ON | `SleepDisabled=Yes`, 화면은 정상 동작 |
| ON | ON | Phase 1 결과대로 동작하는지 |

순서 의존성도 본다 — A→B 와 B→A 결과가 같아야 한다.

### 2-2. C4 (인증 다이얼로그 블랭킹)
A 를 `keepScreenOff` 켜고 실행 → 화면이 꺼진 뒤 B 의 시작 버튼을 누른다.
- 인증 다이얼로그가 보이는가
- 입력 중 화면이 꺼지지 않는가 (유예 10초 안에 못 치면 꺼진다)
- 대응이 필요하면: B 토글 중에는 A 의 재블랭크를 일시 정지

### 2-3. C5 (중지 범위)
A 만 중지했을 때 B 가 켜진 채 남는지, UI 에서 그게 명확히 보이는지.

### 2-4. 종료 경고
- A 만 ON → 경고 없이 종료 (잔류 없음)
- B 만 ON → 경고 뜸
- 둘 다 ON → 경고 뜸, 문구는 B 에 대해서만

### 2-5. 인증 취소 경로
시작/중지 각각에서 암호창을 취소했을 때 버튼 상태가 바뀌지 않는지 (낙관적 갱신 금지).

### 2-6. 강제 종료 복원
B 를 켠 채 `kill -9` → 재실행 → 버튼이 ON 으로 보이는지.

### 2-7. 다국어
신규 문자열이 ko/en/ja 에서 모두 나오는지. 누락 시 키 문자열이 그대로 보이므로 육안 확인 가능.

## Phase 3 — 실물 확인

AC 전원 연결, 외장 모니터 없음, 덮개 30초 닫았다 열기.
통과 기준: `pmset -g log | grep -i "Clamshell Sleep" | tail -1` 에 새 항목이 없을 것.

2026-09-12 데몬 검증 때의 성공 기록(18:24:45 닫음 → 18:25:41 엶, 그 사이 `Entering Sleep` 없음)과
같은 결과가 나와야 한다.

## 실패 시 분기

- **T2 실패**(화면이 안 꺼짐) → 동시 실행 설계를 포기하고 상호 배타로 전환하거나,
  B 가 켜져 있으면 A 의 화면 끄기 기능을 비활성화하고 이유를 표시한다. spec.md 의 Scope 결정을 갱신.
- **T3 실패**(화면이 깨어남) → B 토글 직후 A 가 화면을 다시 끄도록 연동하거나, 사용자에게 안내.
- **T4 에서 맥이 잠듦** → B 가 시스템 잠자기를 못 막는다는 뜻이므로 기능 전제가 무너진다.
  (2026-09-12 덮개 테스트가 통과했으므로 가능성은 낮다.)
