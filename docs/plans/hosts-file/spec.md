# spec — hosts 파일 열기

## 요구사항
"etc hosts 열기 기능" (2026-11-14 사용자 요청)

## 확정된 결정
| 결정 축 | 확정 내용 | 근거 |
|---|---|---|
| 범위 | 앱은 **편집기로 열기만** 한다. 내용은 읽기 전용으로 보여주고, 저장은 편집기가 한다 | 사용자 선택. `/etc/hosts` 는 `root:wheel 644` — 앱이 덮어쓰면 관리자 권한·백업·실패 처리를 떠안는다 |
| 배치 | 새 Tool 이 아니라 **로컬호스트 Tool** 안, 포트 목록 아래 | 사용자 선택. hosts 는 이름→127.0.0.1 을 정하는 파일로 로컬 개발 서버와 같은 맥락. 버튼 몇 개에 탭 하나를 쓰지 않는다 |
| 편집기 | 버튼 옆 메뉴로 열 앱을 고르고 **기억**한다. 처음엔 시스템 기본(지금 TextEdit) | 사용자 선택. TextEdit 는 root 파일을 저장 못 하고 VS Code 는 관리자 인증으로 저장한다 |
| 편집기 목록 | 앱 목록을 자동으로 만들지 않는다. 메뉴 = 고른 앱 · 시스템 기본 · 다른 앱 고르기… | LaunchServices 목록이 쓸 수 없었다(context.md). 선택 화면의 미리보기와 다른 점 |
| 미리보기 | 주석·빈 줄을 뺀 항목 줄만, 고정폭. 탭을 열 때와 앱이 다시 앞으로 올 때 다시 읽는다 | 편집기에서 고치고 돌아오면 바로 반영돼야 한다. 폴링은 늘리지 않는다(`docs/power.md`) |
| API | 넣지 않는다 | 에이전트는 파일을 바로 읽을 수 있고, 에이전트 호출로 GUI 편집기가 뜨면 스페이스가 바뀔 수 있다 |

## 논의에서 생략한 축
| 결정 축 | 생략 이유 |
|---|---|
| 권한·보안 | 앱이 쓰지 않으므로 관리자 권한을 다루지 않는다 |
| 호환성 | 기존 설정·API 계약 변경 없음 |
