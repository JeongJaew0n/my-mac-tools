# spec — 앱 업데이트

## 요구사항
사용자 지시(2026-11-23, 세션마스터 대리 입력): 화면 왼쪽 위 앱 메뉴(MyMacTools)에 "업데이트…" 항목.
GitHub 의 이 저장소를 기준으로 지금 설치된 것보다 새 것이 있는지 보고, 있으면 받아서 바꾼다.

> 2026-11-24: **기준·판 비교는 `docs/plans/app-versioning/spec.md` 가 대신한다** — main 커밋이 아니라
> 최신 GitHub Release 의 버전(semver)으로 판단하고 그 태그를 받아 빌드한다. 아래 표의 '기준'·'판 비교' 행은 그 전 결정이다.

## 확정된 결정
| 결정 축 | 확정 내용 | 근거 |
|---|---|---|
| 기준 | GitHub `JeongJaew0n/my-mac-tools` 의 `main` 최신 커밋 | 사용자 선택. 릴리스·태그가 없고 늘 main 에 바로 푸시한다 |
| 받는 법 | 앱 전용 사본(`~/Library/Application Support/MyMacTools/Update/source`)에 받아 이 맥에서 `scripts/build-app.sh` 로 빌드 | 사용자 선택. 개발 저장소는 건드리지 않는다 — 커밋 안 한 작업이 있을 수 있다 |
| 판 비교 | 빌드할 때 커밋 번호를 앱 `Info.plist` 의 `MyMacToolsCommit` 에 새긴다. GitHub compare API 로 설치된 커밋과 main 을 비교 | 앱 버전(1.0.0)은 바뀌지 않아 비교에 못 쓴다 |
| 확인 창 | 지금 판과 새 판 사이 커밋 제목 목록 + 업데이트/나중에 | 사용자 선택 |
| 도는 중 | 잠자기 방지·덮어도 작업·화면 가리기가 돌거나, 속도 측정 중이거나, 캡처 편집 창이 열려 있으면 **막고 이유를 보인다** | 사용자 선택(앞의 셋). 뒤의 둘도 앱이 꺼지면 잃는 것이라 같은 규칙에 넣었다 |
| 바꾸기 | 앱이 스스로 끝난 뒤 따로 띄운 도우미 스크립트가 설치된 앱을 보관하고 새 앱으로 바꾼 뒤 켠다 | 실행 중인 앱이 자기 번들을 바꾸면 안 된다 |
| 실패 — 받기·빌드 | 지금 앱은 손대지 않고 이유와 빌드 기록 끝부분을 보인다 | 사용자 질문의 전제 |
| 실패 — 새 앱이 안 켜짐 | 보관한 이전 판으로 되돌리고 다시 켠다. 되돌린 앱은 켜질 때 그 사실을 알린다 | 사용자 선택 |
| 켜졌다는 신호 | 새 앱이 켜지면 `Update/launched-<커밋>` 파일을 쓴다. 도우미가 이 파일을 기다린다 | 프로세스가 떴다가 바로 죽는 경우까지 잡는다 |
| 기다리는 시간 | 30초 | **정한 값.** 이 맥에서 앱이 켜지는 데 걸리는 시간(1초 안팎)보다 넉넉히. 근거가 생기면 고친다 |
| 자동 확인 | 하지 않는다. 메뉴를 눌렀을 때만 GitHub 에 묻는다 | 요구는 메뉴 항목이다 |
| 네트워크 | GitHub REST API(인증 없음, 공개 저장소) · `git clone/fetch`. User-Agent 는 `MyMacTools` | 이메일 등 개인 정보를 보내지 않는다 |

## 논의에서 생략한 축
| 축 | 이유 |
|---|---|
| 정식 서명·공증 | 이 맥에서 빌드하므로 ad-hoc 서명 그대로 돈다 |
