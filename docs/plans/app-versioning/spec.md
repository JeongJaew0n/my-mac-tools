# spec — 앱 버전(semver)과 릴리스

## 요구사항
사용자 지시(2026-11-24): 앱 업데이트에 시맨틱 버저닝을 도입한다. 0.x.x semver 로 번호를 매기고
(jjw-app-init 규칙 — 기능 추가는 MINOR, 버그 수정은 PATCH), 업데이트 메뉴에서 지금 버전과 새 버전 번호를
보이고, 그 번호로 새 버전이 있는지 판단한다.

`docs/plans/app-update/spec.md` 의 "기준·판 비교" 를 이 문서가 대신한다. 받기·빌드·바꾸기·되돌리기는 그대로다.

## 확정된 결정
| 결정 축 | 확정 내용 | 근거 |
|---|---|---|
| 번호 자리 | `Resources/Info.plist` 의 `CFBundleShortVersionString` **한 곳**. `build-app.sh` 가 빌드할 때 같은 값을 `CFBundleVersion` 에 넣는다(원본 Info.plist 에는 `CFBundleVersion` 을 두지 않는다) | 사용자 선택. SwiftPM 에 버전 필드가 없어 macOS 앱의 정본인 Info.plist 를 쓴다. 두 곳에 적지 않는다 |
| 첫 번호 | `0.1.0` | jjw-app-init 규칙의 초기값. 지금 Info.plist 의 `1.0.0` 은 한 번도 올린 적 없는 기본값이라 버린다 |
| 올리는 규칙 | 기능 추가·호환 깨짐 → MINOR(`0.3.4`→`0.4.0`), 버그 수정·내부 정리 → PATCH(`0.3.4`→`0.3.5`). 1.0.0 으로 올리지 않는다 | jjw-app-init 규칙 |
| 릴리스 꼴 | 태그 `v0.y.z` + GitHub Release. 업데이트는 `releases/latest` 만 본다 — 태그만 밀어서는 업데이트에 잡히지 않는다 | 사용자 선택 |
| 내는 때 | 사용자 요청 하나를 마칠 때 Claude 가 `scripts/release.sh` 로 낸다. 기능이 하나라도 들어갔으면 MINOR, 수정·정리만이면 PATCH. 문서만 바뀐 요청은 내지 않는다 | 사용자 선택 |
| 번호 올리는 커밋 | `release.sh` 가 번호를 올린 Info.plist 만 담은 커밋(`Release 0.y.z` + 한 줄 요약)을 만들고, 그 커밋에 태그를 단다 | 번호와 태그가 같은 커밋을 가리켜야 한다. 그 전 커밋으로 빌드한 앱은 이전 번호를 갖는다 |
| 첫 릴리스 | `release.sh initial` — `v*` 태그가 하나도 없을 때만, 번호를 올리지 않고 지금 번호에 태그를 단다 | 0.1.0 을 0.2.0 으로 건너뛰지 않으려고 |
| 새 버전 판단 | 최신 릴리스 태그의 번호 > 설치된 앱의 번호 이면 새 버전. 같거나 작으면 최신 | 사용자 요구. 릴리스 뒤 main 에 쌓인 커밋은 다음 릴리스 전까지 보이지 않는다 |
| 받는 것 | main 최신이 아니라 **그 릴리스 태그의 커밋**을 받아 빌드한다 | 보여 준 번호와 설치되는 것이 같아야 한다 |
| 빌드 확인 | 새 앱의 번호 = 릴리스 번호, 커밋 = 받은 태그의 커밋, 서명 확인 | 기존 확인(커밋·서명)에 번호를 더한다 |
| 창 | 지금 버전(`0.1.0 · abc1234`)과 새 버전 번호, 그 사이 커밋 제목 목록, 업데이트/나중에. 최신이면 GitHub 최신 릴리스 번호를 함께 보인다 | 사용자 요구 + 기존 확인 창 결정(커밋 목록) |
| 커밋 목록 | compare API 로 `설치된 커밋...v새번호`. 설치된 커밋이 GitHub 에 없으면 `v지금번호...v새번호`, 그것도 없으면 목록 없이 번호만 | 로컬에서 빌드한 앱은 커밋이 GitHub 에 없을 수 있다 |
| 릴리스가 없음 | "아직 낸 버전이 없음" 으로 보이고 업데이트 버튼이 없다 | `releases/latest` 가 404 |
| 이 기능 전 빌드 | 지금 설치본(63974d5, 번호 1.0.0)은 예전 코드라 main 커밋으로 비교한다. 한 번 업데이트하면 main 최신(이 기능 포함)으로 바뀌고, 그 뒤로는 번호로 비교한다 | 예전 코드는 바꿀 수 없다 |
| `MyMacToolsCommit` | 남긴다. 창에 함께 보이고, 켜졌다는 신호 파일 이름과 빌드 확인에 쓴다 | 번호만으로는 로컬 빌드를 구별하지 못한다 |

## 논의에서 생략한 축
| 축 | 이유 |
|---|---|
| 사전 릴리스(`-beta`)·빌드 메타데이터 | 쓰지 않는다. 태그는 `v` + 숫자 셋만 받는다 |
| 릴리스 노트 본문을 창에 보이기 | 창은 커밋 제목 목록을 그대로 보인다(이미 정한 확인 창). 릴리스 본문은 GitHub 쪽 기록용 |
| 자동 확인 | 그대로 하지 않는다 |
| API 로 버전 보이기 | 요구에 없다 |
