# spec — finder-path-copy

## 목표
Finder 에서 고른 항목의 **절대경로를 지정한 전역 단축키로 클립보드에 복사**한다.

## 왜 만드는가 — macOS 기본 기능으로는 안 되는 지점

Finder 에는 이미 같은 기능이 있다. `⌥⌘C`, 메뉴로는 `경로 이름으로 복사`
(`Finder` 바이너리의 `cmdCopyAsPathname:`).

**문제는 이 키를 바꿀 수 없다는 것이다.** 시스템 설정의 "앱 단축키" 는 메뉴 제목이 정확히
일치해야 하는데, 이 항목의 제목이 선택 내용에 따라 바뀐다.

```
"N48_V2" => "‘^1’의 경로 이름을 복사"          ← 파일명이 들어간다
"N48_V3" => "^0개의 항목을 경로 이름으로 복사"  ← 개수가 들어간다
```

제목이 고정이 아니므로 재지정이 불가능하다. 원하는 키로 쓰려면 앱에서 해야 한다.

## 확정된 결정

| 결정 축 | 확정 내용 | 근거 |
|---|---|---|
| 선택 항목 읽기 | AppleScript `tell application "Finder" to get selection` | 검토 중 실제로 읽히는 것을 확인했다 |
| 단축키 | 기존 `HotKeyCenter` 재사용 | 손쉬운 사용 권한 없이 동작하는 것이 이미 검증돼 있다 |
| 다중 선택 | 줄바꿈으로 전부 이어붙인다 | 여러 개를 골랐으면 여러 개를 원하는 것이다 |
| 따옴표 | 씌우지 않는다 | Finder 기본값과 같게 둔다 |
| 선택 없음 | 조용히 아무것도 하지 않는다 | 클립보드를 비우면 직전에 복사해둔 것을 잃는다 |
| Finder 활성 여부 | 따지지 않는다 | 다른 앱에서 붙여넣으려고 누르는 것이 주 용도다 |
| UI 위치 | 네 번째 탭 | 기존 탭 구조를 따른다 |

## 필요한 권한

**자동화(Automation).** 최초 1회 "MyMacTools 가 Finder 를 제어하려고 합니다" 가 뜬다.
`Info.plist` 에 `NSAppleEventsUsageDescription` 이 없으면 **묻지도 않고 거부**되므로 반드시
넣는다.

거부됐을 때는 `-1743` 이 돌아온다. 이 경우 조용히 실패하지 말고 화면에 사유와 조치를
보여준다. 사용자가 시스템 설정에서 직접 켜야 하기 때문이다.

### 재빌드하면 권한이 풀리는가

TCC 는 코드 서명에 권한을 묶는다. 이 앱은 ad-hoc 서명이라 걱정했는데, 소스가 같으면
재빌드해도 해시가 같은 것을 확인했다.

```
designated => cdhash H"aed0539f...e4"
빌드 전: CDHash=aed0539f...e4
빌드 후: CDHash=aed0539f...e4   → 동일
```

다만 **코드를 고쳐 빌드하면 해시가 바뀐다.** 그때 권한을 다시 묻는지는 확인하지 않았다.

## 선행 작업 — `HotKeyCenter` 확장

지금은 단축키를 **하나만** 등록할 수 있다. 화면 가리기가 이미 쓰고 있으므로 그대로는
두 번째를 붙일 수 없다. id 로 여러 개를 다루도록 고친다.

같은 조합을 두 기능에 지정하면 두 번째 등록이 실패한다(검토 중 `-9878` 확인). 실패를
삼키지 말고 화면에 알린다.

## 범위 밖

- 상대경로·URL·`file://` 형식
- 경로 가공(따옴표, 이스케이프)
- Finder 외 다른 앱의 선택 항목

## 완료 조건

- [ ] 지정한 단축키로 Finder 선택 항목의 절대경로가 복사된다
- [ ] 여러 개를 고르면 줄바꿈으로 전부 복사된다
- [ ] 아무것도 안 골랐으면 클립보드가 그대로다
- [ ] 자동화 권한이 없으면 사유와 조치가 화면에 보인다
- [ ] 화면 가리기 단축키와 동시에 동작한다
- [ ] 같은 조합을 두 기능에 지정하면 알려준다
- [ ] 문자열 3언어(ko/en/ja)
