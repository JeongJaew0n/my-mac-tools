# spec — thermal

## 목표

일곱째 Tool **발열**. 이 맥이 지금 얼마나 뜨거운지를 두 겹으로 보인다.

1. **OS 의 판정** — `ProcessInfo.thermalState` 의 네 단계(정상·약간 높음·높음·위험)
2. **실제 온도 °C** — 센서를 묶음별로 최고·평균, 그리고 펼치면 센서 전체

## 확정한 결정

| 결정 축 | 확정 내용 | 근거 |
|---|---|---|
| 배치 | **새 Tool (일곱째 탭)** | 사용자 결정 (세션마스터 경유, 2026-11-06) |
| 판정 | `ProcessInfo.thermalState` 를 그대로 쓴다. 바뀌면 `thermalStateDidChangeNotification` 으로 받는다 | 공개 API, 권한 없음. **"몇 도부터 뜨겁다" 는 우리가 정하지 않는다** — 경계를 지어내지 않는 규칙 |
| 판정 색 | 정상·약간 높음 → 초록, 높음 → 주황, 위험 → 빨강 | Apple 문서상 `serious` 부터 시스템이 성능을 줄인다. 그 전까지는 "조치 불필요" 다 |
| 온도 출처 | 비공개 `IOHIDEventSystemClient` — PrimaryUsagePage `0xff00`, PrimaryUsage `5`, 이벤트 종류 15(temperature) | Stats·iStat Menus 가 쓰는 경로. sudo 없이 센서 46개를 읽었다(실측, M3 Pro). 공개 API 에는 °C 가 없다 |
| 비공개 API 호출 | `dlsym` 으로 찾는다. 못 찾거나 센서가 0개면 "읽지 못함" 으로 보이고 판정은 그대로 | 링크 시점에 묶이면 심볼이 사라진 macOS 에서 앱이 아예 안 뜬다 |
| 묶음 | 이름 앞부분으로 가른다: `PMU tdie` → **SoC 다이**, `NAND` → **SSD**, `battery` → **배터리**, `PMU tdev` → **PMU 기기 센서**. 나머지는 묶지 않고 전체 목록에만 | 뜻이 분명한 것만 이름을 붙인다. `PMU tcal` 은 51.9°C 로 고정된 보정값으로 보여 최고값을 왜곡한다 — 뜻을 모르는 센서를 최고값에 섞지 않는다 |
| "CPU 온도" | **쓰지 않는다** | Apple 이 센서 뜻을 공개하지 않았다. 다이 온도를 CPU 라 부르면 확인하지 않은 주장이 된다 |
| 숫자 | 묶음별 **최고 · 평균**, 소수 한 자리 °C | 같은 이름이 두 번씩 나온다(서비스가 둘). 최고·평균은 중복에 흔들리지 않는다 |
| 읽는 곳 | 백그라운드 큐 | 한 번 훑는 데 약 35ms(실측). 메인에서 2초마다 하면 프레임을 놓친다 |
| 갱신 | 탭이 보이는 동안만 **2초마다**(tolerance 20%) | 온도는 메모리보다 빨리 변한다. 다른 목록과 같은 규칙 — 안 보이면 훑지 않는다 |
| 팬 속도 | **넣지 않는다** | sudo 없이 읽히는지 확인하지 않았다 |
| 메뉴바 | 넣지 않는다 | |
| API | `thermal.info` | 다른 Tool 과 같은 원칙 |

## 완료 조건

- 탭이 보이는 동안 값이 2초마다 바뀌고, 다른 탭으로 가면 읽기가 멈춘다
- `thermal.info` 가 화면과 같은 값을 준다
- 센서를 못 읽어도 판정 줄은 보인다
- ko/en/ja 문자열, README·api.md·용어집 갱신
